# 项目状态

更新：2026-11-19。阶段：LangGraph 开发版本，Runtime 修订为 `langgraph_v1`。

## 已实现

本地/云端原生工具协议、多轮控制台、本机 Web、官方 Retail 环境、schema 和身份/订单归属检查、精确参数确认、写后回读、有限修正、身份失败输入记忆、请求去重、执行轨迹、官方 Orchestrator 与 Evaluator 接入，以及四种对照方法的入口。

CLI、Web、Benchmark 已改为共享 LangGraph 节点和条件边，使用 SQLite 检查点、用户和官方工具结果的 interrupt 暂停恢复，导出实际图及可读状态。原手写编排循环已替换。当前仅支持同一进程内恢复，跨进程完整会话恢复尚未实现。

extended 环境还提供注册和购买，使用独立 SQLite 及写回执；这部分不是官方 Retail Benchmark，不能混入官方成绩。

## 已有证据与边界

- 2026-11-19 清理后的 LangGraph 验收：93 项离线测试通过，0 failure、0 error；包含原有 86 项和新增 7 项图编排测试。官方 Orchestrator 的换货回放仍可由 Evaluator 判为 reward=1.0，但这是离线给定模型回复的契约测试，不是真实模型效果结论。本次官方数据库、已有扩展 SQLite 的前后哈希一致，收费模型请求为 0。云端 CLI 配置检查也通过，未请求模型。
- 已有有限本地模型只读交互及云端开发对话，曾发现数量误解、错误反馈冲突、错误环境选择等问题。这些是开发案例，不是统计成功率。
- 测试回放证明给定消息下程序能正确执行，不证明 LLM 会生成同样轨迹。
- 固定协议的真实模型对照、泛化和违规率测量尚未完成，没有公布提升百分比或 Benchmark 排名。

## 近期解决的执行问题

1. 不再用历史购买关键词误伤取消订单的正常补问；实际写入仍需精确核对单。
2. 购买核对单显示已有、本次新增、提交后数量，旧订单不会自动取消或合并。
3. 查询失败后记录身份输入状态，不再反复推荐同一失败输入；姓名/邮编不能来自邮箱子串。
4. 缺信息走正常 `ask_user → waiting_user`；模型不遵守时使用标注来源的程序补问。
5. 不确定写入和回读不一致时停止，避免自动重复执行。
